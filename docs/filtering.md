# 过滤与热键

什么该显示，什么该丢掉。判据在 `core/events.js` 的 `isAllowedSequence()`。

## 三种模式

| 设置页显示 | 存的值 | 行为 |
| --- | --- | --- |
| Off — All Keys | `none` | 全部显示 |
| **Hotkeys** | `modifiers` | 起手键是修饰键才显示，用内置集合 `Ctrl, Shift, Alt, Super, Fn, Function` |
| **Custom** | `custom` | 只用你自己填的 Allowed Keys 列表，同样只看起手键 |

**容易踩的一点**：Hotkeys 模式**不看** Allowed Keys 列表，它用的是内置修饰键集合。
设置页里那个输入框只在选中 Custom 时才可编辑（`enabled: filterSetting.value === "custom"`），
所以选着 Hotkeys 填列表是存不进去的。

判据只有一行：

```js
return set.includes(labels[0]);
```

`labels` 是当前按住的键、**最早按下的排在前面**，所以 `labels[0]` 就是这次手势的**起手键**。
起手键命中集合，整组都显示（包括后面那些普通键）—— 组合键才完整可见。

所以 **`Ctrl` 必须先按**：`Ctrl+C` 显示，`C+Ctrl` 不显示。列表里写了 `Space`，
那 `Space+A` 显示、`A+Space` 不显示。这与上游 `ignoreEvent(pressedKeys[0])` 一致。

逗号这个键要写成 `Comma`，不能用 `,`。

## 松开的键不参与判定

`labels` 只含**物理按住**的键。松开的键还能在屏上停留到淡出，但它不在 `heldKeys` 里，
所以**不能替下一个键背书**，也不再是「这一组」的成员（见[事件模型](event-model.md)）：

```
Ctrl 按下 → 松开 → 按 R   →  只显示 Ctrl，R 不借到修饰键身份
```

## 代价：两键真同时按下时，结果由内核报序决定

内核上报顺序不受控。真正在同一毫秒按下 `Ctrl` 和 `C` 时，谁先到是竞态，
而**谁先到就决定这组显不显示**。上游也是这个行为。

换来的是规则干净、可预测：**先按修饰键**才是快捷键，反过来不是。
要让普通键也一起显示，用 Off — All Keys。

## 鼠标和滚轮同样过闸

keyviz 把点击、拖拽、滚轮都直接送进 `onKeyPress`，由同一道闸决定。
所以裸点击、滚轮默认不显示（它自己是起手键，也不是修饰键），
而 `Ctrl+点击`、`Ctrl+滚轮` 显示 —— 修饰键要先按住。

单独开关鼠标事件的是 `showMouseEvents`（旧的 `showMouseClicks` 仍然认）。

## 被拒的键会继续挡着，但不留任何痕迹

门禁拒绝时，这个键**仍会进 `heldKeys`**（只是不建行）。而它是最早按下的那个，
所以**只要它还按着，它就是起手键**，之后按什么都会被一起拒掉：

```
C 按下（被拒）→ Ctrl 按下（一起被拒）→ C 松开 → Ctrl 按下 → 只显示 Ctrl
```

这是「只看第一个键」的直接后果，不是 bug。想让 `Ctrl+C` 显示，就先按 `Ctrl`。

**但被拒的按下不画任何东西。** 事件层维护两个集合：

| 集合 | 含义 | 谁用 |
| --- | --- | --- |
| `heldKeys` | 物理按住的键（被拒的也在里面） | 门禁判定、鼠标/滚轮过闸、松开时的自我纠正 |
| `shownKeys` | 真正**上屏**的按住（`heldKeys` 的子集） | 渲染层：键帽的按压姿势 |

所以被拒的 `C` 不会凭空出现键帽，**也不会让上一行里同名的 `C` 键帽播放按压动效**。

原则是：**门禁拒绝 = 屏幕上什么都不发生**（不给键帽、也不给按压姿势）。
否则门禁刚说"这不是快捷键"，界面却在给它做反馈，自相矛盾。
