# 生命周期

键帽在屏幕上活多久，以及计数什么时候归零。**两者是同一个期限。**

## 一条时间线

```
按下 ──────► 按住（永不过期）─────► 松开 ──────► fadeTimeout ──────► 退场动画 ──► 消失
             │                                  （从松开这一刻起算）
             └─ 计数一直累加                      └─ 计数仍然有效        └─ 计数归零
```

| 阶段 | 时长 | 由什么决定 |
| --- | --- | --- |
| 入场动画 | 250ms（默认） | `animationDuration`，`animationType` 为 `none` 时是 0 |
| 按住中 | **无限** | 只要还在 `heldKeys` 里就不过期 |
| 松开后停留 | **5000ms**（默认） | `fadeTimeout`，可设 0–60000 |
| 退场动画 | 250ms（默认） | 同 `animationDuration` |
| 位移重排 | ≈83ms | `animationDuration / 3` |

**计时从松开开始，不是从按下开始。** `release()` 会把该键的 `lastPressedAt` 刷成当前时刻，
所以按住多久都不算数。重新按下也会刷新，连续操作能一直续命。

## 过期怎么执行

`Daemon.qml` 里一个 50ms 的 Timer 调 `Events.tick()`，判据是：

```js
now - key.lastPressedAt < config.fadeTimeout   // 或者：这个键还按着
```

这个 Timer **只在有内容时运行**（`groups.length > 0`），空闲时不轮询。
一个键过期后，如果整行都空了，整行一起消失；渲染层会先标记 `dying` 播完退场动画再删。

## 计数与显示对齐

**键帽消失 = 手势结束 = 计数归零。** 修饰键和普通键都是这个规则。

```
Ctrl×3，等 6 秒消失，再按  → Ctrl×1
Ctrl×3，不停顿直接再按     → Ctrl×4     （键帽还在，计数继续）
A×3，等 6 秒消失，再按     → A×1
```

实现上，`tick()` 会在暂定键已不在任何行中时丢弃暂定状态（`pending`），
`pendingRepeat` 同理（它是关于某一行的问题，行没了就作废）。

这里曾经错位过：修饰键的计数挂在暂定状态上，而它既不随松开也不随过期清除，
于是计数能跨过消失无限延续（等十分钟再按也是 `Ctrl×4`）；普通键没有这套机制，
随行归零。同一个手势两种规则。现在统一了。

**副作用**：`fadeTimeout` 同时决定"键帽停留多久"和"计数保留多久"。
想让计数更"粘"，只能调大 `fadeTimeout`，键帽也会多停留同样久。

## 几个特例

- **滚轮**：没有按下/松开，静止 **300ms** 后视为松开（keyviz 的 `SCROLL_LINGER_MS`），
  然后走正常的 `fadeTimeout`。
- **拖拽**：按住鼠标移动超过阈值（默认 **50px**）后，按键的键帽被 `Drag` **替换**，
  不是新增一个。松开时释放的是 `Drag`。
- **历史模式**：开了 `showEventHistory` 后每行按同样规则过期，
  `maxHistory`（默认 5，可设 1–50）只限制同时保留几行。
  所以历史模式**不会**让旧行永久停留——它们照样到期淡出。
